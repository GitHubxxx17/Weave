# Weave Skills Complete Vertical Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship builtin, enabled-plugin inline, project and user Skills with explicit selection, progressive reads through the shared Tool Pipeline, durable provenance and Studio selection/retry/history in one independently reviewable topic.

**Architecture:** Protocol owns pure wire types, Session projects append-only facts, Runtime supplies actual turn identity and generic loader tools, plugin owns declarative governed contributions, and plugin-host performs inert disk validation. Server composes all sources in pinned Generations and owns preparation, resource state, audit receipts and HTTP; Studio mirrors only the HTTP contract.

**Tech Stack:** TypeScript strict ESM, Zod, Node filesystem/crypto within plugin-host and Server, existing Hono/React stack, `yaml` as one documented exact-pinned plugin-host dependency.

**Spec:** `docs/superpowers/specs/2026-11-22-skills-design.md`; the reviewed spec and this plan were recorded on the fresh Skills branch before implementation.

## Global constraints

- Use a fresh branch from latest `origin/main` after marketplace PR #92 integration. Do not reuse merged acquisition/marketplace branches.
- Existing Plugin API `1.0.0` stays accepted; add optional capability/contribution vocabulary, retain strict unsupported-manifest rejection before import.
- No new workspace package; plugin-host depends internally only on plugin; Studio imports no `@weave/*`, Node or Electron module.
- `SkillRef` always includes `id`, `instructionSha256`, `bundleSha256`; resource-only changes make refs stale.
- All model reads run through shared Pipeline and real admitted `sessionId/turnId/toolCallId`; no active-session singleton or plugin observer used for required audit.
- Disk roots: project `.weave/skills`, project `.agents/skills`, configured `<dataDirectory>/skills`; no ancestor or implicit third-party-home scan.
- No Skill grants permissions or executes code; existing tools govern execution.
- Exact retry preserves linked full user message including images, exact refs and recorded provider/model/parameters/permissions.
- No dedicated Skills history route/helper; use existing Session detail turns and projection.
- No fake ESM for pure Skills. First-class skill-only installable distribution, developer CLI/scaffolding and custom panels are later topics.
- Do not commit, push or merge unless root's authorized workflow performs that step.
