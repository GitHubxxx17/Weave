# 插件制品仓库的绑定与独占

Stage 6.2b 为 Server 增加受控的制品仓库封装。它依赖 6.1 的不可变制品 API
和 6.2a 的授权数据库，保证遵守协议的多个 Server 不会同时操作同一仓库。
本阶段提供内部基础能力；安装 HTTP、选中来源、Generation 接入和 Studio
安装操作分别由后续切片完成。

## 两个数据库各自负责什么

主数据库保存既有信任、安装和操作日志，并新增 schema marker 与一条根目录
登记事件。根目录中的 `ownership.sqlite` 只保存一条绑定事件，并承担存活期间
的独占锁。绑定包含数据库 UUID、规范主数据库路径、仓库 UUID、规范根目录和
owner 数据库路径。它不选择插件，也不授予任何信任。

主数据库仍使用短事务。owner 数据库使用 DELETE rollback journal，并设置
零 busy timeout；获取后在私有连接上保留 `BEGIN EXCLUSIVE`，直到消费者退出。
不使用 PID、心跳、超时夺锁或自动重绑定。

## 获取顺序与中断恢复

获取顺序固定为：完成主数据库的短读取 → 提交根目录绑定 → 获取 owner 生命周期
独占事务 → 提交一致的主数据库登记 → 创建唯一的 6.1 制品存储实例。等待 owner
锁时不持有主数据库事务，主数据库正常读写不被这个独占锁覆盖。

首次绑定必须显式使用 `allow-unbound`。根目录可以为空，也可以含有结构合法的
6.1 制品和暂存目录；已有制品仍然没有选择或运行权限。`require-bound` 不创建
owner 文件或绑定。新 owner 文件用 `wx` 和 0600 权限保留，只有成功创建该文件
的一次调用可以初始化 schema。

如果进程在根绑定提交后、主登记提交前退出，完全一致的数据库 UUID 和路径可以
继续登记。不同数据库、复制到另一位置的数据库、原路径上重新创建的数据库和
另一仓库都不能接管。未知空文件、损坏文件和缺失 schema 不会被自动修复；主登记
存在但 owner 文件丢失也不会被重新创建。绑定失败可能留下惰性的元数据，错误会
保留失败阶段和内部原因。

Node 24.4 的 SQLite 接口没有可用的“读写但禁止创建”打开选项。已有文件打开前后
检查临时文件身份，并且绝不对未知文件执行修复 SQL。可检测的替换会失败；竞态下
原生打开仍可能留下惰性的空文件。这不是针对同一操作系统用户恶意替换的原子沙箱。

## 路径、结构与元数据边界

允许符号链接祖先，使用原生文件系统解析父目录后再检查最终叶子。主数据库、owner
以及托管后代不能是符号链接或特殊文件；普通文件要求单链接。主数据库打开前后保存
临时 device/inode 身份，在 managed 操作时复查；它不会作为重启后的持久身份。
比较不使用数据库大小、修改时间或目录链接数。

主数据库和它的 journal/WAL/SHM 不能落在制品仓库内。SQLite sidecar 后缀的大小写
变体也被保守保留，前缀通过文件系统查找与主数据库身份匹配，以免在大小写不敏感
的文件系统上创建阻塞 SQLite 写入的目录。

每个发布 payload 最多 1,000 个文件、20 MiB、2,000 个条目和 64 层目录；发布
对象和暂存操作分别最多 64 个。暂存操作根不计入条目，内部可选的 payload 包装层
计入，因此其总界限为 2,001 个条目和从操作根起 65 层目录。所有扫描均有界，遇到
链接、特殊文件、未知条目或超限立即拒绝，不执行插件、不重新计算内容摘要，也不清理
暂存目录。

未绑定仓库在任何创建或绑定前完整扫描，持锁后再检查。已绑定仓库先检查固定根条目、
身份及 sidecar，拿锁后才递归扫描 payload，以免竞争者读取另一个合法 owner 正在
变化的 staging 内容。持锁期间的普通操作边界只复查身份和数据库状态，不扫描全部
制品。

主数据库的 marker 与根事件表只在两者均不存在时一起创建；缺少其中一张、marker
为空或不合法等可检测损坏会失败，不修复。marker 记录 schema 初始化，不是另一份
绑定。如果外部删除登记行，或在重启前删除这两张表，可能与未登记或旧版数据库无法
区分。本实现不承诺识别任意 SQL、磁盘元数据删除和修复行为。

## 操作、丢失和退出

受控封装只创建一个私有的 6.1 存储。`stage` 和 `read` 按原有队列顺序立即派发，
使用一个完成票据集合统计活动与排队调用，不增加第二个调度队列。每个调用把用户
取消信号与私有的所有权丢失信号组合起来。

首次观察到锁、路径或主授权数据库失效时，封装在同一同步调用栈内保存失败状态、
中止丢失信号、调用同步观察者，然后抛出错误。已经排队而尚未开始的 6.1 调用会在
文件系统访问前看到取消。已经发出的原生 I/O 只能在现有取消边界停止。观察者只能
返回 `undefined`；异步返回、thenable 和抛错都会保留在错误原因中，不能授权恢复。

普通用户取消和制品损坏不等于锁丢失。正常 `quiesce` 立即拒绝新调用，等待已派发
调用完成，并继续持锁；它不触发丢失信号。后续 composition 必须先停止新管理请求
和回合接纳，等待制品工作及所有使用旧路径的 Generation 消费者退出，才能关闭仓库
租约，最后关闭主授权数据库。

关闭通过 ROLLBACK 和原生 close 释放锁，不提交应用事实或删除内容。并发关闭共享
一次清理；失败后可以重试剩余清理，且不会恢复操作接纳。主操作、观察者和清理错误
共同保留，不能把不确定的释放报告为成功。

## 验证范围

针对注册、路径和租约的真实本地 SQLite 测试覆盖初始化、严格重放、损坏拒绝、
事务回滚、文件替换、目录界限和关闭重试。热 journal 用例使用 SQLite 生成的未提交
磁盘镜像与 rollback journal，确认由 SQLite 恢复原绑定；它不是掉电保证。

独立 Node 子进程验收使用现有工具链编译 Server 到唯一的临时输出，不覆盖共享
Server dist。IPC 事件有缓冲和期限，进程退出且管道关闭后才清理数据。18 个用例在
macOS 15.6.1 / Darwin 24.6.0 arm64、Node 24.4.0、SQLite 3.50.2、pnpm 10.13.1
上全部通过，无跳过。它们覆盖真实锁竞争、SIGKILL 后接管、绑定事件字节稳定、持锁
期间主库写入、两个根竞争同一主库、登记失败释放、SQL 预置的半绑定恢复，以及路径和
结构策略。测试的正常关闭在 owner 成功释放后才关闭 authority。

运行 `pnpm exec vitest run apps/server/test/plugin-store-lease-process.test.ts` 会先
构建 Server 的工作区依赖，再编译唯一的临时 Server 输出。CI 使用的 Linux 结果由对应
PR 的检查记录补充；本机证据不延伸到未验证的平台、网络文件系统、突然断电或 Electron。
