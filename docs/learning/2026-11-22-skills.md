# Skills: usage, authoring and provenance

Skills are instruction bundles with optional text resources. They guide the Agent
through existing tools. A Skill does not create a tool, grant permissions, execute
its scripts, or bypass workspace and approval rules.

## Using Skills in Studio

Choose Skills beside the conversation composer. The picker shows the source,
description and instruction preview. Selections belong to the current Session's
draft and keep their order. A newly accepted send removes only the selections
actually sent; navigation and a failed send preserve the appropriate draft.

The Agent receives the selected instruction bodies at turn admission. It also
receives a bounded metadata catalog and may use `read_skill` to load another
applicable Skill progressively. It must follow continuation cursors to EOF before
reading that bundle's resources with `read_skill_resource`. Both tools use the
ordinary shared Tool Pipeline. Resources are inert UTF-8 text, including files
under a `scripts/` directory.

History distinguishes requested selections, instructions prepared for the model,
model loader results delivered to the conversation, and failed reads. A prepared
badge does not claim that the model consumed or followed the instructions. Model
delivery requires a matching successful, untruncated durable tool result at EOF.

Exact retry uses the linked original user message, including images and original
content ordering, exact Skill references, provider/model, effective sampling,
reasoning setting and permission mode. Later provider defaults and current UI
selections do not change that request. Older history without a complete snapshot
offers a clear unavailable state for exact retry. A changed or removed Skill is
reported explicitly; a same-name replacement is never substituted silently.

## Sources and installation

The current catalog composes four sources:

| Source          | Location or contribution                                 | Authority                                  |
| --------------- | -------------------------------------------------------- | ------------------------------------------ |
| Builtin         | Weave-authored `weave-planning`                          | Ships with Server                          |
| Enabled plugin  | Governed `skills` SDK contribution                       | Existing plugin trust and generation rules |
| Current project | `<project>/.weave/skills` and `<project>/.agents/skills` | Only the Session's bound project root      |
| User            | `<data directory>/skills`                                | Server-configured root                     |

`WEAVE_SKILLS_DIR` or `StartServerOptions.skillsDirectory` overrides the user root.
Explicit `skillsDirectory:false` disables only user disk discovery. No ancestor,
other product's home directory or remote source is scanned automatically. Root
changes require refreshing selections. Missing directories are empty; unreadable,
invalid, changed or capped entries make catalog diagnostics visible.

This slice reads disk bundles and enabled ESM plugin contributions. A first-class
skill-only installable artifact, developer packaging and official marketplace
distribution follow in the next topic. No fake ESM entry is needed to use a
project or user Skill.

## Authoring SKILL.md

Create one directory per lowercase dash-separated name:

```text
.weave/skills/review-change/
  SKILL.md
  references/checklist.md
```

```markdown
---
name: review-change
description: Review a proposed change for correctness and missing validation.
user-invocable: true
disable-model-invocation: false
metadata:
  author: Your team
---

Read the relevant diff and surrounding contracts. Use references/checklist.md
when needed. Report actionable findings with evidence and verify each claim.
```

The directory and `name` must agree. A description and nonblank instruction body
are required. YAML supports quoted and block strings, a string-valued `metadata`
map and the two boolean invocation flags above. Bounded unknown extension strings
are inert metadata. Richer unknown mappings/sequences, aliases, duplicate keys and
unsupported types are rejected. This deliberately bounded format does not claim
full compatibility with every upstream Skill frontmatter variant.

BOM and CRLF are normalized for instructions. References include a source-qualified
ID, instruction SHA-256 and whole-bundle SHA-256. The bundle identity also includes
the name, description, invocation flags and sorted resource identities. Editing only a resource
invalidates an old selection. Source labels are shown without absolute filesystem
paths in public responses.

Disk bundles are bounded to 64 KiB per SKILL.md, 8 KiB frontmatter, 1000 files,
20 MiB total and depth 8. Each source admits at most 128 candidates; discovery
shares a 64 MiB read budget. Selection accepts at most 32 references and 1 MiB of
explicit instruction bodies. Model catalog JSON is at most 32 KiB; progressive
page JSON is at most 4096 bytes and must also fit the actual token budget. Clipping
and incomplete discovery are reported. Symbolic links and special files are
rejected; only exact standard macOS top-level `/var`, `/tmp`, `/etc` aliases are
accepted when they point to their corresponding `/private` directory.

## Enabled plugin contributions

An ESM plugin declares `capabilities:['skill']` and its exact contributed names in
`contributes.skills`, then uses `sdk.skillsExtensionPoint` to register
`{name,description,instructions,invocation?,resources?}`. The kernel supplies the
plugin attribution; plugin code cannot claim another owner. Contributions are
copied, validated and frozen before collection. Inline resources use the separate
SDK bounds: 64 resources, 256 KiB per resource and 2 MiB total. See the exported
`SkillContribution` schema for complete bounds.

Plugin API 1.0 remains valid. The capability is additive; an older strict host
rejects an unknown capability before importing a new Skill-contributing plugin.
Disabled or untrusted plugins contribute no Skills to a new Generation. A running
turn retains its admitted Generation; the next turn sees the replacement.

## HTTP and durable evidence

`GET /sessions/:id/skills` returns catalog metadata. Guarded
`POST /sessions/:id/skills/preview` accepts `{skill:{id,instructionSha256,bundleSha256}}`
and returns the exact instruction preview without activation or audit writes.
Existing Agent POST accepts `skills` in selection order. Existing Session detail
exposes `turns[].userMessageId`, `request` and `skills`; it uses no extra history
endpoint. Failure facts may carry `toolCallId` to identify the failed model read.

New request snapshots persist `useProviderDefaults:false` with the effective
sampling values. Absence of a sampling number under that marker means the original
request sent no such parameter. Ordinary callers may omit the marker to retain
provider default resolution.

The required host audit wraps plugin around/result handling. A fabricated,
rewritten, truncated or unaudited loader success stops the turn before another
model request. Audit preparation and the later durable tool result are distinct
facts. Cancellation invalidates turn-scoped cursors and resources, then disposal
drains accepted work before releasing the Generation.

## Verification

Package tests cover schema validation, SQLite restart, exact identities, request
snapshots, middleware identity, filesystem changes, pagination, audit failures,
Generation admission and Studio retry/selection races. Acceptance also used real
loopback HTTP/SSE and SQLite restart with a scripted provider, plus desktop and
mobile Studio interaction. These checks do not require a live model or claim that
an external model will obey instructions.

The pinned [official-content reference audit](2026-11-22-official-plugin-references.md)
records Codex, DeepSeek Harness and Kimi source versions and Weave's choices.
Curated directory membership, publisher authorship, installation, activation and
trust are separate properties.
