# Studio 本地插件安装与验证

Stage 6.3 将已有的受管插件 HTTP API 接入 Studio 和 Desktop。在 Plugins 的「受管插件」区输入已打包 ESM 目录的绝对路径，或在新版 Desktop 选择插件文件夹，然后明确预览、审查并导入。导入只保存候选。执行前需要单独审查并激活目标版本，回退也需要确认具体候选及前选择。

默认 Desktop 使用 `<userData>/plugins`，首次运行允许绑定受管存储。`WEAVE_PLUGINS_DIR` 保留原值交由 Server 解释；未注册的自定义根保持普通本地插件模式。浏览器首次绑定需使用 README 中的显式 owned launcher。Studio 通过 HTTP/SSE 管理插件，原生选择器只返回路径。

## 状态和恢复

候选历史、当前选择、匹配信任和实际发布是不同状态。插件准备失败时，保存的选择仍可能存在，而实际版本为空或仍是先前版本。回执展示决定保存时的结果，最新列表展示后来读取的完整目录。卸载保留候选历史与制品。

停用、撤销信任和卸载默认让已有回合继续。保存状态已达到目标时，仍可再次确认并选择立即生效，发出新的决定以处理保留代际中的旧回合。立即生效沿用 Server 的取消范围：触发取消时会中断所有会话在当前代和退役代运行的回合，包括与此插件无关、当前界面不可见的回合。是否触发由 Server 根据保留的插件代际判定，确认窗口明确说明这一范围。

Studio 一起读取 ESM、MCP 和受管目录，并在 Generation 与 authority 水位检查后整组发布。部分读取失败时保留上一份完整目录。三个来源共享一个写入门；已打开的确认窗口也使用同一条件。

已发送的写请求丢失响应后，App 内存保留原 URL、请求 ID 和 JSON。成功 GET 无法证明这个命令是否已经保存，所以仍需要「重试原请求」或明确停止跟踪。精确重试可能读取已保存决定，也可能首次执行仍满足条件的请求。停止跟踪不撤销原操作。关闭面板不丢失这个槽；关闭或重新加载整个 App 会结束此内存状态。切换 Server profile 时应重新打开 Studio。

## 2026-11-22 开发进程验收

真实 Chromium 经 `http://127.0.0.1:5173` 的 Vite 代理连接隔离 Server。真实 Electron 39.8.10 使用临时 userData 加载编译后的 Main、实际 Preload 和 Studio；HTTP 指向其随机回环端口。所有插件来源、数据库和执行标记均隔离于个人 profile。

| 验证                      | 观察                                                                                                                                                                                                    |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 浏览器与 Desktop 生命周期 | v1 预览和导入不执行；激活 v1 得到真实工具结果。导入 v2 不执行且 v1 继续运行；激活 v2 后回退 v1。卸载清除选择、信任和发布，候选历史保留。                                                                |
| 浏览器故障激活            | Server 返回 committed 200 和固定安全 issue；已保存选择与实际发布分开展示，私有异常不进入公开回执。                                                                                                      |
| 浏览器丢失响应            | 重复导入 no-op 先在真实 Server 保存，再中断回执交付。重开面板与 GET 均不解锁普通写入。重试 URL 与正文逐字节相同，返回相同决定和 unknown 应用状态，没有重复副作用。                                      |
| 浏览器再次立即决定        | 普通停用、撤销和卸载后，各自的新立即命令使用新请求 ID 和当前水位，返回 changed=false；卸载后的目标摘要为 null。六次确认默认未勾选立即生效，完整披露 Server 全局影响；延迟回执期间三个来源仍共用写入锁。 |
| 三方目录与旧管理界面      | MCP 单次 GET 失败时保留完整旧目录。普通 ESM 的信任、停用、启用，以及 MCP 的创建、编辑、信任、移除通过；MCP 停用入口在共享写入门占用时保持禁用。                                                         |
| 窄屏及键盘                | 360×640、640×420 可折叠和重开面板。完整 manifest 审查可进入 Tab 循环并滚动，Escape 恢复触发焦点，文档无横向溢出。                                                                                       |
| Desktop 原生选择          | 真实 NSOpenPanel 取消保持路径不变；选择填入原始绝对路径。选择过程没有预览或安装请求。                                                                                                                   |
| Desktop 重启              | 正常退出后移走原始来源目录，同一 profile 仍恢复已选择 v1、两个候选及真实工具结果；随后卸载仍保留历史。                                                                                                  |

验收工具有两项明确差异。CUA 读取 Electron 默认菜单的原生辅助功能树时触发菜单模型循环，因此选择器验收的临时启动器在实际 Main 导入前抑制默认应用菜单；生产代码没有这项修改。错误根测试临时截获 `showErrorBox` 记录真实标题和消息，再由原 Main 的 `app.exit(1)` 退出，未做原生错误框视觉验收。两项记录均不代表打包安装产物已验证。

负向 fixture 对照在隔离目录补跑，确认过早执行标记和错误活动版本会被断言发现；初次正向浏览器验收前的负向对照时间缺少留存证据。每次实际预览和导入前后仍检查了版本标记与活动身份。

## 当前取舍与后续

沿用 App Store 和现有三个 GET，可以保持一套目录与写入门，但客户端需要有界对账，不能把它当作跨 Server 实例的原子事务。受管头逐项不下降，旧目录与回执分别保留；若将来支持跨实例恢复，需要新增协议身份。

原生 chooser 使用显式能力位和用途校验；旧 Desktop 壳退回手输路径。默认根可首绑，自定义根需显式授权，避免把既有手动插件目录隐式转换为受管根。窄屏沿用同一面板状态，使用右侧固定面板和内部滚动。

这些选择延续 Foundation 中已核对的 Codex 执行身份绑定、Kiro 配置与激活分离、DeepSeek Harness 串行管理和资源释放原则。Weave 保留自己的 Session、Tool Pipeline、Generation 和权限边界。

下一阶段是固定版本的 GitHub 获取，然后才是静态 Catalog。远程来源、构建、签名、自动更新、制品回收和跨 App 重启的请求恢复均需各自的设计与验证。
