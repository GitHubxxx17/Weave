# 插件市场：发现、安装和运行的边界

插件市场从左侧导航打开，占用导航栏之外的主区域。发现页用于浏览官方内置插件和
需要安装的官方或社区固定版本，已安装页保留本地插件、GitHub 获取、受管版本历史和 MCP 管理。
右侧继续展示运行活动与可信插件贡献的[声明式面板](2026-11-22-plugin-panels.md)。

## 使用与维护目录

默认的 Weave 目录来自仓库中的 `marketplace/index.json`，社区投稿保存在
`marketplace/submissions/`，通过生成工具整理和校验。默认目录已收录
`weave-official-skills@1.0.0`，提供使用指南、插件开发、技能创作和 MCP 配置四项
可单独选择的技能；固定来源与校验见[官方技能指南](2026-11-22-official-skills.md)。
社区列表仍为空。开发者投稿流程见 [发布指南](plugin-marketplace-publishing.md)。

发现页支持管理多个索引源：添加 HTTPS JSON 地址或 GitHub 文件地址，切换来源后
显式刷新，才会读取远程目录。添加与移除来源的配置以追加记录持久保存；刷新失败
保留上次成功的数据，并显示缓存已过期。索引中的发布者署名来自该索引，不表示
Weave 已验证其身份。移除一个来源不会卸载或停用已安装插件。

服务端也支持 `WEAVE_PLUGIN_MARKETPLACE_CATALOG` 指定的绝对路径；嵌入式
启动可传 `startServer(..., { pluginMarketplaceCatalogFile: '/absolute/catalog.json' })`，
显式传 `false` 则忽略该本地覆盖项，仍保留默认目录和用户添加的来源。本地文件在
启动时读取，修改后需重启。`GET /plugins/marketplace` 和来源列表只读取缓存，
不下载、不导入、不重载或确认信任；远程读取仅由明确的刷新操作触发。

最小有效目录是：

```json
{ "schemaVersion": 1, "plugins": [] }
```

每个 `plugins` 元素包含以下字段。这里的 `source` 和 `manifest` 必须填写真实发布
的固定版本；不能把移动的分支名作为提交，也不能直接把 Harness/npm 包当作 Weave
已打包插件。

| 字段                             | 含义                                                                                 |
| -------------------------------- | ------------------------------------------------------------------------------------ |
| `id`                             | 插件 ID，需与每个版本的 `manifest.id` 一致                                           |
| `name`、`description`            | 展示名称和介绍，作为普通文本显示                                                     |
| `publisher`                      | 索引维护者提供的发布者署名，社区分类不因此变成官方认证                               |
| `tags`                           | 搜索标签                                                                             |
| `releases`                       | 发布版本数组，每项包含完整 `manifest` 与 `source`                                    |
| `releases[].manifest`            | 与 `weave-plugin.json` 完整一致的受管插件清单，含显式 `contributes` 和 `permissions` |
| `releases[].source.repository`   | 规范的小写 `https://github.com/owner/repository`，无 `.git` 后缀                     |
| `releases[].source.commit`       | 完整的 40 位小写十六进制提交 SHA                                                     |
| `releases[].source.subdirectory` | 仓库内相对目录，根目录用空字符串                                                     |

目录上限为 512 KiB、100 个插件、每插件 20 个版本、10 个标签。服务端拒绝未知
字段、重复 ID、重复版本、受保留 ID 和无效清单。版本按数字语义降序；API 版本、
运行宿主和 `engines.weave` 按 Weave 现有规则计算兼容性。安装器仍会独立复查实际
内容。文件不可读、超限或不符合格式时，所选索引显示不可用，不输出本机路径和
原始错误，也不影响 Agent 启动。

开发者先生成包含 `weave-plugin.json` 的单文件 ESM 或声明式 Skills 包，将其发布到公开
GitHub 仓库，再把完整清单、固定 SHA 和子目录提交给目录维护者审阅收录。
当前交付包括仓库 PR 投稿、条目准备、目录生成、CI 校验及静态索引订阅；独立账号、
网页上传审核服务、签名和评分尚未实现。官方分类由宿主内置名单或固定的完整发行元组决定，索引不能自行写入
官方分类。完整 source/manifest 匹配的 GitHub 官方包仍需要安装、审阅和独立激活；
内置插件展示“随应用提供”。具体身份与旧宿主兼容行为见[官方指南](2026-11-22-official-skills.md)。

## 一次安装经过哪些步骤

1. 在发现页选择一个兼容版本，点“准备安装”，把该版本交给已安装页的 GitHub 表单。
2. 点“预览插件”，通过原有获取器下载固定内容并校验文件。
3. 将实际返回的来源和完整清单与所选目录版本比较。任何不一致都拒绝进入导入审阅。
4. 在原有审阅弹窗检查实际权限、扩展声明、目录摘要、固定提交和发布者署名。
5. 确认导入后产生不可变候选，不加载插件。
6. 单独审阅并激活候选，Server 才通过原有协调器发布新 Generation。

市场文字不是运行授权。安装不运行 Git、包管理器或构建脚本；信任与工具审批继续
遵守既有边界。GitHub 获取仍受匿名接口配额限制。

页面组件可以卸载，但 App 继续持有管理 Store，包括未确认操作的冻结请求和共享
写入门禁。切换导航后返回，重试仍发送相同请求 ID 和请求体。待完成的预览会取消，
过期响应不能重新打开弹窗。对话和右侧活动组件通过隐藏保留实例，运行中的 SSE、
草稿、终端 PTY、预览 iframe、标签顺序和宽度继续保留。

旧版本保存在右侧的 `plugins` 标签会单独移除，其余有效标签的实例 ID、顺序和
固定状态保留；如果原活动标签被移除，选择第一个有效标签。不会因为一条旧标签
重置整份布局。

## 设计依据

首次设计核对 Harness `2e39e70496aa02986ca6a820c5d497e816b69d7e`，索引扩展又核对
2026-11-22 的 `d98f5d68519215da48f3002da2cb9c9d2068d81d`。其目录发现、生成和
安装相互分离，当前没有官方在线索引。Weave 采用这一职责划分，增加自己的仓库默认
目录与 PR 投稿规则，继续使用不可变制品和显式激活；没有采用其 pnpm 安装和构建授权
模型。具体来源链接和 Codex/Kiro 的既有执行、配置边界
见 [Foundation](../architecture/foundation.md) 与
[设计契约](../superpowers/specs/2026-11-22-plugin-marketplace-design.md)。

## 2026-11-22 初始市场验收记录（索引扩展前）

全仓库 `pnpm check` 已通过格式、ESLint、TypeScript、测试与全部构建，共 3,495
项测试。其中 Server 1,261 项、Studio 624 项。新增目录测试覆盖 23 项读取、
来源分类、保留 ID、兼容性、边界与启动隔离行为。独立复核分别检查 Server 合同
和 Studio 导入/导航流程。

实际 Vite、HTTP Server、SQLite 与文件系统的浏览器验收使用临时社区目录及确定性
GitHub 上游测试数据，跑通发现、详情、版本交接、预览、导入和单独激活。导入后
记录为安装序号 1、信任序号 0、选择/信任/发布均空、Generation 1；单独激活后
信任序号变为 1，实际发布进入 Generation 2。该证据证明市场与现有安装流程的
集成，不代表公开社区仓库的实时可用性。

浏览器检查了 1440 像素桌面、macOS 标题栏留白和 390 像素手机宽度；手机页面无
横向溢出。独立复核发现较矮窗口中的长内容原先被裁切，修复独立滚动区域后在
800×600 窗口验证底部 MCP 操作可达。实际浏览器也确认旧 `plugins` 标签迁移后
终端/预览 ID 和固定状态保留、导航往返保留对话节点和草稿；运行流、终端连接
保活与原样重试另有应用行为测试覆盖。

设计、实现和文档没有加入新依赖。GitHub 公网获取的匿名配额限制仍遵循 Stage 6.4
验收记录；市场阶段没有绕过匿名权限，也没有把临时测试条目发布到默认目录。

## 2026-11-22 多来源与投稿工具验收

索引扩展已通过全仓库 `pnpm check`：格式、ESLint、TypeScript、3,547 项测试和
全部构建，其中 Server 1,303 项、Studio 634 项。`pnpm marketplace:generate`
与 `pnpm marketplace:check` 验证了当前真实空目录。新增覆盖来源配置的追加保存、
重启恢复、损坏日志保护、严格 JSON/HTTPS 限制、超时/大小限制、缓存保留、来源
切换竞争、移除结果不确定后的恢复，以及实际安装版本与选择框的一致性。

独立复核检查了 Server/Studio 合同与开发者工具链，发现的两个 Studio 状态问题
已修复并补回归测试。全量测试另发现新增目录 drain 延迟原有同步取消的问题，
调整关闭顺序后，工具取消时重入 `stop()` 仍得到同一 Promise；目录仍在宿主和
存储释放前完成收尾。对应关闭与集成测试已单独复核。

实际浏览器使用真实 Vite、HTTP Server、SQLite 和文件系统，远程目录及 GitHub
源为确定性测试数据。验证添加来源只发送配置写入、刷新后浏览、来源署名、再次
刷新遇到无效数据时保留旧目录、页面重载、移除后切换到有效来源，以及固定版本
交接到原有预览审阅。另用重新创建管理器验证配置重启恢复为尚未读取，未联网。

1440 像素桌面与 390×844 手机检查通过，手机目录管理区域没有横向溢出。验收中
发现手机工作台的固定活动面板遮挡导航，已将其起点移到 54 像素顶部导航下方，
普通窗口及 `hidden-inset` 均可正常进入插件市场。浏览器与临时服务均已停止。
没有把测试条目放入默认目录，也未部署 Pages、创建发布账号或替开发者发布插件。
