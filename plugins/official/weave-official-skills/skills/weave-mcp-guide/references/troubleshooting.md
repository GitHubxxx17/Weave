# MCP 故障分流

收集最少事实：Weave 运行模式/Server 所在系统、配置 ID、非敏感错误码、是否已信任/
启用、当前 Generation、health/stale/draining。不要请求秘密值、Authorization header、
环境 dump 或未脱敏程序输出。没有管理读取工具时指导 UI 核对，不虚构 API 工具。

| 现象                     | 先检查                                   | 后续动作                                          |
| ------------------------ | ---------------------------------------- | ------------------------------------------------- |
| 新服务未启动             | 保存和信任/启用是否分开完成              | 用户审阅规范配置后再决定                          |
| changed/untrusted        | launch 字段与信任摘要是否一致            | 重新审阅，恢复旧值不自动恢复                      |
| environment refs 失败    | 引用变量名、启动宿主时是否设置           | 用户修正宿主环境后显式重载                        |
| executable/cwd 失败      | Server 本机真实路径、执行位、依赖        | 修正路径或由用户安装依赖，不用 shell 拼接         |
| 启动后退出/协议错        | stdio 程序、版本、stdout 日志污染        | stdout 仅协议，诊断写 stderr；检查脱敏错误        |
| loaded 但无某工具        | 实际发现目录、新回合、tool namespace     | 以真实工具 catalog 为准，不按文档臆造调用名       |
| stale                    | 服务发出 tools/list_changed              | 目录冻结，由用户显式全量重载，不自动重放          |
| 409 冲突                 | authority sequence/config 是否被别处改变 | 重新读状态并重新打开表单/审阅，不替换序号自动重试 |
| 目录暂未同步             | 两个控制面 Generation 是否一致/请求失败  | 保留最后一致目录，写入停用到刷新恢复              |
| 决定保存但 applied:false | 持久决定与重建错误分别查看               | 排查失败后用户显式重载                            |
| 连接上限/关闭失败        | 当前/候选/排空共享32连接上限             | 不反复重载；排查进程，必要时重启宿主              |

单个服务失败隔离。关闭失败不释放配额，不能靠再添加配置规避。最多8个未移除有效
配置，每服务工具目录最大64项（实际协议/结果限制仍适用）。CLI 文档有命令不表示
Weave 已安装对应第三方 server。当前不支持远程 MCP、Resources/Prompts、自动市场
安装程序或账号连接；需要这些能力时准确说明缺口，不能用配置草稿冒充完成。
