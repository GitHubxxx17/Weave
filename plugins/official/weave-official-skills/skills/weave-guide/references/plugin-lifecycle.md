# 从目录到运行版本

## 四层事实

1. 目录条目描述可发现的插件版本，不是实际安装状态。GET/页面挂载读取缓存，不执行插件。
2. 来源预览核验实际来源的 manifest、文件与摘要；查看不导入，也不替用户授信。
3. 导入创建受管不可变候选。候选存在不代表已激活。
4. 激活/信任决定构建符合条件的新 Generation。正在运行的回合保留其已接纳版本。

“安装好了怎么没有工具”需要按这个顺序核对。先到“插件市场 → 已安装”确认实际
候选和激活状态、错误及当前 Generation，再看目标 Session 是否开始了新回合。
不要仅依据发现页的名称、publisher、兼容提示或旧工具列表作出结论。

## 来源

本地导入选择实际 payload 目录。CLI build/pack 的容器还包含 receipt.json；应选择
容器内 payload 子目录。receipt 是本机事实，不是签名、远端出处或信任决定。

GitHub 来源限定公开仓库、规范 https://github.com/owner/repository、真实完整小写
40 位 commit 和精确子目录。分支、tag、短 SHA、未来提交和本地 receipt 都不能代替。
安装器不会运行 npm install、编译源码或生命周期脚本。ESM 必须提前生成单文件入口；
纯 Skills 使用 schema-2，无 entry。

发现页可添加多个 HTTPS JSON/GitHub 文件索引源，显式刷新才读取远端。刷新失败保留
旧缓存并标过期。移除索引源不卸载/停用已经安装的插件。目录署名和精选收录不等于
作者身份认证、官方分类、trust 或 activation；官方身份由宿主决定，不能靠填写 Weave。
本内容包本身是否正式发行需要看宿主真实目录，不从 README 推断已上线。

## 变化与回合

更新、回滚、停用、撤销依既有 managed lifecycle 生效。内容变更需重新审阅真实摘要；
本地 ESM、managed artifact 与 MCP 配置信任有各自状态；不能用单纯恢复文件替代
管理页中的实际授权状态。默认新代用于下一回合，旧回合可以排空。
MCP 的立即生效选项会取消所有当前和退役代进行中的回合，可能涉及其他 Session。
界面解释操作范围后由用户执行，模型不绕开管理页调用写接口或编辑数据库。

如果“决定已保存，但重建失败”，持久事实和运行事实不同。保留错误信息，指导用户
检查冲突/失败来源后显式重载；不能把旧代仍有工具描述为新版本已成功加载。
