# 产品、入口与设置

本内容针对 main e7dd7ca80dfa71d46fa73b5a5b6dffbb1ae8ad49 的产品契约；固定来源见 source-notes.md。

## 常用入口

插件市场是 Studio 左侧导航的一页，占用主内容区域。发现插件用于浏览目录、
搜索、查看某个固定版本的声明和管理索引源；已安装用于本地导入、GitHub 获取、
受管候选/版本历史、本地 ESM 和 MCP 管理。MCP 位于“插件市场 → 已安装 → MCP 服务”。
旧文档“右侧添加插件面板”不是当前主插件入口。右侧运行活动和主市场各有用途。
可信 ESM 插件可以贡献右侧声明式面板，用户从添加面板菜单打开。面板读取同一插件
实际注册的持久事件；表单只准备可编辑草稿，用户明确发送。主插件市场仍在左侧。
插件缺失或撤销后保留不可用标签占位，不通过旧标签保留插件授权。

Session 是一段持久对话及其事件历史。Agent 回合从确定的 Generation 获取工具和
插件组合；调用通过共享 Tool Pipeline 进行输入验证、权限策略、审批、取消和结果处理。
Studio 通过 Server HTTP/SSE 使用 Runtime，网页不直接 import 插件或启动 MCP 进程。
插件架构不等于插件获得任意工作区权限；在进程内受信任 Node 插件也不等于 OS 沙箱。

## Provider 与请求参数

先区分浏览器开发模式和 Desktop。浏览器开发模式的 Provider 来源通常是宿主启动
配置，设置界面保持只读；Desktop 由 Server 配置编排和 Electron 系统密钥能力保存。
公开状态展示已配置/密钥是否存在等事实，不回显 API Key。不要索取密钥诊断。

可用 Provider 描述包含默认模型、contextWindowTokens、temperature、maxTokens 等
有界设置。上下文窗口是预算输入；它不能扩张远端模型的真实上下文能力。temperature
和 maxTokens 受当前提供方和请求校验约束，不承诺所有模型支持相同参数。以实际界面
可见字段为准；不要编造连接测试、模型自动发现或任意 reasoning 选项已实现。

精确重试使用原请求已保存的实际参数；稍后改变 Provider 默认值不会悄悄改变它。
普通重新发送新消息可采用当时生效的选择和默认值，两者不要混淆。

## 诊断顺序

先定位产品面（市场/已安装/MCP/会话/Provider）、读取状态及错误，再选择相关资料。
目录为空并不能证明插件已卸载；市场来源失效并不能证明已装插件失效。当前工具不可用
也可能是当前回合仍持有旧代、来源未激活或目录诊断失败。按显示事实分流，避免重复
信任、全量重载和重启作为默认万能处理。
